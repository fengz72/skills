# 需求访谈与执行接入

先读现有模型、配置、样例和环境；可调查的事实先调查，只就缺失业务选择和无法确认的材料询问用户。逐轮聚焦会改变路线、修改边界或验收结论的问题，SE 持续更新设计、区分事实/假设/未决项，测试检查可验收性。此方法随包提供，不依赖 grill-me；用户显式指定外部 skill 时不冒充已经调用。

## 需要收敛的内容

| 内容 | 设计必须写明 |
|---|---|
| 模型身份 | PyTorch/ONNX、权重/外部数据、前后处理、版本或校验值 |
| 唯一路线 | source→export→runtime，例如 PyTorch→ONNX→GE Session，或 ONNX→ATC→OM→ACL；不默认并跑多后端 |
| 输入输出 | dtype、shape/动态范围与维度关系、合法值/空输入、输出业务语义与 TopK/ID/顺序规则 |
| 正确性 | 独立参考或已确认 expected、测试覆盖、数值与业务阈值、NaN/Inf 策略 |
| 修改边界 | 是否允许改图、权重及其存储精度、计算/累加精度、运行时、pass/kernel、编译器/全局环境；已有授权优先 |
| 性能 | p99 数值/单位/计时与统计方法、吞吐单位、到达模型与代表性输入分布、错误/超时/积压、缓存与冷启动 |
| 资源与预算 | 主机/容器/物理设备、核/内存、实验次数/时长/重试/停止条件、稳定性持续时长与判据 |
| 交付 | 目标运行/兼容范围、代码/图/OM/依赖、样例、配置、复现、报告、数据与案例共享边界 |

用户不知道 QPS 时，不阻塞需求阶段；由 [目标推荐 skill](../../npu-performance-target/SKILL.md) 给附依据和可信度的参考范围，不擅自新增硬性门槛。不能从只有模型文件推断生产请求分布。

低精度与混合精度是可提出的优化候选；设计需写明允许的转换范围、必须保留的输入输出类型、精度和业务门槛。已有用户授权允许在门槛内调整计算精度时可直接推进实验，不逐项重复确认；明确要求原始 FP32 或限制精度时遵守该边界，不能把技能包含此手段当作具体模型已授权转换。

不擅自改变原始参考、业务阈值、权重内容或全局 CANN/驱动。权重 dtype 转换也要纳入已允许的精度范围，并保留原始材料。普通实现细节由角色解决，不逐项抛给用户。

## 最小 runner 接入

复用项目已有 runner 前，用真实小样例验证版本、产物与路径。没有 runner 时，把所选路线缺失的入口作为开发任务：导出/构建、加载执行、参考比较、benchmark，profiling 按需补。不是每条路线都需要导出或 ATC，也不要求公共 Python API。

为每个实际入口记录：命令及 argv/配置、实际主机/容器/cwd、依赖与模型/样例身份、超时、退出码、结果/日志位置、异步完成/同步边界和清理方法。基础入口失败先处理可运行性，不用随机输出生成 expected。

模型运行入口没有端到端负载能力时，报告已测的范围，并开发所需入口；不得把模型调用时间写成服务端 p99。导出和具体参数从当前安装包、同版本头文件/样例或官方文档核实，不凭来源仓旧示例推定支持。

## 单模型设计确认

每项关键需求有可执行测试方法，未知事项不会改变下一步行为时可继续独立调查；影响路线/精度/性能结论的缺口保持未决，不宣称通过。SE/测试为统计量、有限预算和稳定性方案提出具体建议，再作为本模型设计确认，不要求用户独自给出所有技术参数。
