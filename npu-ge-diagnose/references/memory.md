# 内存归因与输出缓冲生命周期

## 先分清测量对象

用现有监测和阶段采样区分 Host 进程 RSS/地址空间、设备 HBM、应用输入/输出缓冲、GE/Runtime 模型及工作区。不能把设备总占用全部归于当前图，或把地址空间预留等同于实际驻留。按设备、进程、图/模型、时间窗口记录数值与单位。

在初始化、构建/加载、首轮、稳态、shape 切换、模型卸载、Session 销毁和进程退出前后比较。组件分配日志或已安装且匹配版本的报告工具可进一步归因；缺工具时仍分析采样与分配/释放，不宣称得到了该工具特有的复用率或理论下界。

静态图的内部内存分析关注峰值活跃集合、生命周期重叠、对齐、跨流依赖、不可复用区和外部 IO。动态路径关注池容量、形状切换、缓存、碎片和回收时机。不要将仅支持静态图的离线重放直接用于动态池；单次空报告也不能证明动态图。

## 以接口契约决定输出策略

先读取当前 GE Session/ACL 接口与现有 runner 实现，列出每个输出的描述、大小取得阶段、内存位置、分配者、所有者、完成边界和释放方式。不要由输入 shape 或模式编号猜测输出容量。

| 当前接口实际提供的契约 | 分配与复用方法 |
|---|---|
| 编译/加载后确定各输出所需容量，调用方提供缓冲 | 从本次编译结果/模型描述取得容量，按要求分配一次；后续完成后复用。实际输出逻辑大小与分配容量分开保存。 |
| 输出 shape 动态，但接口给出有效容量上界且接受调用方缓冲 | 按已核实上界或当前需求分配，运行前满足容量契约；切换更大输出时，在旧工作完成后扩容。重新核对返回描述和有效字节数。 |
| 输出大小只有执行时才可得，由运行时或分配回调管理 | 遵循接口的动态输出/allocator 契约，执行完成后取得实际描述与数据；不能塞入零字节占位缓冲并假定运行时会补齐。 |

一张源动态模型经固定形状编译后可能符合第一项；源输入固定也可能产生数据依赖输出。当前接口若没有可用的动态输出路径或容量契约，应记录缺口并补实现或澄清约束，不能写成已支持。

容量涉及 dtype、布局、padding、对齐和溢出检查，逻辑元素数乘字节数不一定等于物理所需字节数；以接口提供的物理大小为准。零长度输出是否合法按当前算子/接口确认，不能统一当失败或跳过。

## 可核查的生命周期

1. 分配：记录输出槽、容量、位置、所有者和对应模型版本。申请失败时清理已取得的自有资源，保留原错误。
2. 提交：当前请求独占其写入区。输入、输出、描述对象及所需临时区活到接口规定的完成点；不同在途请求不得写同一区域，除非接口明确保证安全。
3. 完成：同步调用按契约确认返回即完成；异步调用依据完成事件/回调或同步边界。提交成功不等于设备完成。
4. 取回：按实际返回 shape/dtype/有效字节解释输出。消费者仍引用底层缓冲时保留租用，或做明确复制；不能让下一轮覆写用户尚在读取的结果。
5. 复用/扩容：只有旧请求及其消费者完成后才回池；容量够且布局/接口兼容才复用，容量不足按契约重新分配并更新绑定。不能先释放旧内存再等待旧设备工作。
6. 释放：正常关闭、部分构造失败、执行错误、取消和模型重载都清理自有资源。先处理在途工作再释放缓冲，按接口逆序销毁包装对象。借用、运行时持有的地址不由应用直接释放，使用其指定释放或归还方法，避免双重释放。

无法确认失败后设备是否仍访问缓冲时，不立即归还给其他请求；按当前运行时契约终止/等待/销毁执行上下文，并记录清理结果。Session/ACL 的具体顺序和 API 以目标接口核实，不复制另一入口的释放逻辑。

## 地址与泄漏验证

地址对账区分编译 offset、加载期逻辑地址、每轮用户 IO 地址和实际 kernel 参数地址。静态内部区可能采用基址加 offset，但用户 IO 替换或地址刷新会改变实际下发地址；动态图的分配/释放也需按本轮执行关联。只有日志/trace 明确支持时才建立映射，不能把未实际分配的逻辑地址当成设备访问地址。

持续增长是线索。用稳定 shape 长跑、大小 shape 交替、重复创建/销毁和正常退出对照缓存高水位、动态池保留与泄漏；查未配对分配、所有权丢失或引用滞留。短期平台不能单独证明绝无泄漏，单次释放后设备数字未降也不足以证明泄漏。

缓冲修复至少验证受影响的静态/动态输出、容量增长和复用、交替 shape、异常清理、重复初始化/销毁。并发目标存在时验证请求与输出对应及读后覆写问题。重跑参考精度和业务输出；测试未覆盖的接口路径明确列出，不用一次正常返回代替生命周期正确性。
