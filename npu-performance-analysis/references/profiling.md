# 采集与瓶颈分解

## 采集一份可归属的数据

1. 保存本次模型、代码（含必要未提交改动）、运行配置、芯片、设备/核预算、CANN/驱动、命令和退出码。记录主机/容器、进程、图/模型身份、输入 shape/dtype、实例数、并发和 batch。
2. 用当前环境 profiler 的帮助、安装文档或同版本样例确认其真实采集入口和能力。采集最终 GE Session 或 ACL 执行命令；不强制使用 torch_npu.profiler，不为采集改变交付路线。复用现成 runner，缺少入口时补当前任务所需的最小调用。
3. 单独保留代表性稳态采集，必要时另采新 shape、缓存未命中或尾部场景。标明采集开销；正式性能结果来自独立的无采集轮次。
4. 检查真实文件与字段。`op_summary`、`kernel_details`、`op_statistic`、`api_statistic`、`step_trace`、`trace_view`、msprof trace 只是常见线索，名称、单位和列随版本变化。先读表头、时间基准、导出完整性和重复行。
5. 按明确身份选择目标进程、图和窗口，排除其他任务与重复导出。启动/预热排除只按事先契约；测量窗口中的新 shape 编译、缓存未命中或加载不得事后删除。无法确定迭代数时保留聚合统计，不能默认一轮后报告单请求耗时。

输出保留原始文件和解析/选择方法，图表或摘要能回溯原始行与时间段。不要求专用来源脚本：可用已有 profiler 导出与当前可用解析工具完成；若为重复任务补脚本，验证单位、重复行、窗口与错误路径后再使用。

## 从墙钟到热点

- 先定位同批请求/迭代的提交、H2D、设备执行、D2H、同步和输出就绪。异步 API 返回通常不能证明设备已完成；以完成边界和时间线核对。
- 汇总算子类型与实例的 count、total、average、max，附 shape、dtype、Cube/Vector 等实际执行信息。热点表用于排序，kernel 耗时总和不直接等于端到端时间。
- 在时间线上检查依赖、overlap、提交空洞和同步。嵌套事件不能双计，多流/多实例事件不能直接相加当墙钟；需要时计算区间并集，同时说明它只表示占用范围，不证明处于关键路径。
- 对照单请求关键路径和多请求资源占用。关键路径用于解释延迟，资源竞争用于解释吞吐与尾部；单请求时延倒数不是设备并发容量。
- 检查 Host 准备输入、高频 API、格式/dtype 转换、分配释放、提交间隙、数据拷贝与同步。在本次总占比和可解释时间段上提出结论，不用通用次数/毫秒阈值直接判瓶颈。
- 将总体结果按约定 shape、长度、业务类别或缓存状态分组，避免轻请求掩盖尾部类别。不能事后选择分组改变已确认 SLO。

只有聚合数据时可以提出“累计成本高”的判断，不能声称已找出 p99 根因；补请求—执行关联或尾部时间线验证。

## 推荐/打分模型的候选生成

| 观测证据 | 最小验证与候选 | 需要防止的误判 |
|---|---|---|
| 多输入、碎片拷贝、H2D 占比高 | 区分真实字节数与调用开销；尝试连续打包、减少重复传输、缓冲复用、异步流水 | 打包后额外转换或 Host 工作可能抵消收益；新增等待要计时 |
| 小 kernel 多、Host API 密集、设备间隙多 | 对齐提交与依赖；减少冗余同步、图内整理、已有融合、适用的提交批量化 | API 频繁本身不证明 Host 限制，融合也可能已经发生 |
| Gather/Embedding 等热点 | 核对索引/访问规模、HBM 读写、布局、重复读取与重用 | 随机访存与延迟限制不由计算峰值解释；缓存收益依赖真实分布 |
| 重复结构累计成本高 | 源图与编译图交叉确认；优先检查现有融合，再评估定制 pass | 重复次数不等于收益，外部消费者和布局可能阻止融合 |
| 单实例低利用率且有 p99 余量 | 固定设备资源搜索 batch、并发、实例数，监测内存与竞争 | 不能用 batch×实例数÷单实例平均耗时代替实测 |
| 混合 shape/长度尾部恶化 | 关联编译/cache miss/调度；评估合法分档、预处理、队列或隔离 | 不缩小支持范围，不用不现实的全形状预热制造收益 |

## 将分析变为可比较实验

先声明比较类型：同负载 A/B 用于解释影响；约束内容量比较按相同搜索规则分别寻找两侧满足 p99 的运行点。不同容量点的 p99 可展示，但不能当作同负载延迟收益。

检查负载发生器的计划到达、实际发送、接收、完成和发送滞后；开放到达与固定并发闭环分别解释。目标负载未形成、漏发、计时边界不明或异步未完成时，该点不能作为容量证据。错误/超时/丢弃、队列增长与结束时未完成工作一并记录，不只统计快成功请求。

最终候选在搜索后冻结，由测试使用同契约分布的独立请求序列/种子与新轮次验收；基线同规则复测，必要时交错测量检查漂移。不平均多轮 p99 冒充合并请求 p99。具体样本数、时长、算法与跨轮判定以[测量约定](../../npu-model-workflow/references/measurement.md)和单模型设计为准。
