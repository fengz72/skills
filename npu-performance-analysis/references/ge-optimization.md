# GE 优化方法与验证链

先确认设计允许修改的层和精度；当前任务只沿已选 GE Session 或 ATC→OM→ACL 路线执行。源模型为 PyTorch 不代表 PyTorch eager、torch.compile 或 TorchAir 专用优化会进入交付图。TorchAir 的 GE 模式与 ge::Session 的 graph_run_mode 是不同概念。

## 选择作用层

| 方向 | 实施前依据 | 必需验证 |
|---|---|---|
| 源模型/导出图重写、常量或计算整理 | 允许修改；广播、索引、边界、dtype、数值与动态语义明确 | 导出/图合法；变更保留到最终执行；范围内精度与业务输出通过 |
| shape 分档、布局或转换整理 | 输入支持范围、分档/回退、转换成本、内存与编译规模 | 混合真实负载、等待时间和缓存假设符合契约；端到端结果改善 |
| 编译开关与已有融合 | 目标 CANN 支持该入口、名称、值、作用域、粒度和版本 | 日志/最终图显示实际生效；非忽略配置；正确性与独立性能通过 |
| 定制融合 pass | profiling 成本、完整模式和当前未融合证据 | 注册/加载/调用、正确匹配、最终图变化、执行与性能逐级证明 |
| ONNX 解析插件 | domain/opset、端口、属性、shape/type 与目标 GE 算子契约 | 实际解析入口调用插件，映射正确，后续编译与执行可用 |
| 搬运/缓冲/异步流水 | 本次时间线瓶颈、接口所有权、容量和完成语义 | 请求与输出对应、实际 overlap、稳定性、最终配置 p99/吞吐 |
| batch/并发/多实例 | p99 余量、内存与资源预算 | 成功吞吐、请求尾延迟、错误/超时和队列稳定，不能只看设备利用率 |

接口和参数以目标环境安装包、头文件、同版本样例、帮助与官方文档核实。不要将经验文档中的参数名和值写成所有版本通用命令。GE Session 与 ATC/pyatc 的注册和加载分别验证；某一路线可用不证明另一路线已适配。缺实现工具时提出具体开发任务，不声称包内已提供模板或 kernel。

## 定制 pass 的最小实施流程

1. 固定可复现图片段和输入，说明相较父版本要消除的计算、搬运或提交；先查当前最终图是否已覆盖。
2. 按[图归因](graph-attribution.md)列出完整匹配前提与排除条件，包括外部消费者、控制边、常量值、可选输入、dtype/shape 和动态范围；不满足时保持原图。
3. 使用当前安装版本的注册/API/构建方式实现，固定源码、编译器、链接库和产物身份；加载路径属于执行配置，记录并隔离，避免串用其他实验插件。
4. 通过本次进程日志或其他可验证机制确认库实际加载、pass 进入、匹配数量与图发生预期变化。仅构建成功或注册成功不能证明生效。
5. 检查重复运行/构建、多个匹配和无匹配情形，避免重复改写、错误重入、非预期节点替换及静默扩大匹配范围。
6. 先验证图合法、编译、原始故障与精度/边界，再无 profiler 测量正式路线。融合可能改变浮点累加/转换，必须按设计阈值验证；没有收益也保留记录和证据。

## ONNX 解析映射

先明确原节点的 domain、opset、属性默认值/类型、可选输入输出、常量和索引语义，再确认目标 GE 算子契约及当前解析入口的支持方式。必要 shape/type 推导与属性转换不能省略。

插件库实际加载、映射回调命中和生成目标节点需有证据。解析映射不是 kernel 实现；目标算子/分解或引擎实现缺失时另行评估，不能用“插件成功注册”代替可运行结果。与原语义比较动态范围和边界输入，最后执行选定路线。

## 运行时与负载优化

- 缓冲按编译/运行接口的实际 size、shape、dtype、布局和所有权分配；不要只按输入 shape 推算输出容量。复用前确认旧异步工作完成，容量变化按契约扩容，自有与运行时资源分别清理。
- 异步流水先画输入准备、H2D、执行、D2H、输出消费的依赖；用事件/同步保证生命周期，trace 证明 overlap。删除同步而提前返回不能算优化。
- batch、并发和实例组合在固定资源与工作负载下搜索；批处理等待、排队、竞争、发送滞后、错误和积压均按契约记录，不能用更多未授权硬件或更轻输入制造收益。
- 并发、异步、缓冲改造与最终配置运行请求 ID 对应的正确性压力测试，覆盖混合 shape、复用和允许的生命周期/异常路径；按约定时长检查资源增长和清理。详情见[正确性约定](../../npu-model-workflow/references/correctness.md)。

## 比较、接纳与回退

每个实施使用掌控者分配的 OPT 记录，写明父版本、变更、配置、作用证据和回退；组合另建记录并复验。运行时、pass/plugin、自定义算子、前后处理或 CANN/驱动改变后按影响范围重做功能/精度，不只测性能。

同负载 A/B 与 p99 约束内容量是不同问题。先按同口径搜索，冻结配置，再由测试用独立序列与新轮次验收；最终收益引用验收值，不能用搜索最好一轮。无可行基线时可探索改善可行性，首次可行报告状态转变；不能从零或缺失基线算吞吐百分比，也不能替换已有可行交付基线。

超 p99、精度失败、队列不稳定的结果保留观测值并标“不满足约束”；构建/执行失败填未测得，不能伪造性能。性能下降、无收益、曾接纳后撤回均留存，由掌控者依据独立证据决定接纳；完整测量规则见[测量约定](../../npu-model-workflow/references/measurement.md)。
