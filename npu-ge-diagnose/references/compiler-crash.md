# 编译与执行崩溃

## 保留现场与阶段定界

记录原命令、退出码/信号、时间、PID/TID、模型与外部权重身份、输入 shape/dtype、编译选项、运行配置和完整日志。先区分解析/构图、pass、代码生成、加载、执行与结果处理；日志最后出现的 pass 不一定就是故障所在。

保留 core、当时的可执行文件、实际加载的库及其版本/构建标识、符号和相关源码版本。不要用修改后的同名二进制替换旧现场，或安装不同 debug 包后直接解析旧 core。匹配的独立 debug 符号可用于原二进制；其匹配关系需验证。没有符号仍可保留地址、函数级和阶段判断，不编造源码行。

以栈顶附近的非标准库帧、实际模块映射和调用上下文判断 GE、Runtime、驱动、算子或应用责任。崩在标准库可能由调用方非法状态触发，深层出现 GE 名称不证明 GE 是根因。归属无法确认时写“待定”，继续能完成的阶段分析。

## 按证据能力分析

| 现有材料 | 可支持的结论 |
|---|---|
| 失败描述和日志 | 命令失败、阶段、日志明确报出的错误；不能确认 coredump 内存根因 |
| 完整线程栈和信号 | 崩溃线程、附近函数/模块、候选路径；缺符号时不引源码行 |
| 匹配二进制/符号/源码，缺现场 | 源码候选与数据流假设；未观察到的指针、变量和竞态不写成事实 |
| 同次 core、匹配二进制/库/符号与线程现场 | 可结合指令、访问地址、寄存器及对象状态验证具体假设；优化构建可能缺帧/变量 |
| 稳定最小复现、专项检测或修复前后对照 | 进一步验证根因与修复，不因单次未崩溃就认定已解决 |

缺材料只限制相应结论层级，不要求停下全部分析。报告逐项标注材料“已匹配、缺失、未核实、不一致”，并说明补采哪项能检验哪个假设。错误次运行或错误版本材料不能混成完整证据链。

## 最小现场采集

已有同次完整栈可直接分析。若有 core 且目标环境有 GDB，可在与崩溃架构、库和构建相匹配的环境导出下列信息。命令中的路径需换成已确认的实际文件；该步骤不会启动被调试程序，但会读取可能包含模型/请求内容的现场，产物留在本任务授权位置。

```bash
gdb -q -batch \
  -ex 'set pagination off' \
  -ex 'info threads' \
  -ex 'thread apply all bt full' \
  -ex 'info registers' \
  -ex 'p $_siginfo' \
  -ex 'info proc mappings' \
  -ex 'info sharedlibrary' \
  /absolute/path/to/executable /absolute/path/to/core \
  > gdb-core.txt 2>&1
```

部分 GDB/core 格式不能提供信号详情或映射，保留报错并标记缺失；必要时用 `info files` 检查已加载文件。确认 GDB 选择的崩溃线程，专项寄存器/局部变量采集要切到目标线程/帧，不能拿另一线程的寄存器解释故障。未取得 core 时先检查目标系统现有 core 机制和当前进程限制；仅为本任务在可控会话开启或重现，不擅改全局系统配置。

## 源码与参数追溯

1. 核对 core 与可执行文件/库的构建身份，符号与地址映射，源码 commit。源码可搜索全仓（需要时 `rg --hidden --no-ignore` 并限定已授权仓），不要仅凭文件名猜实现。
2. 实际阅读故障附近函数、调用点和参数构造，区分原始 backtrace 与源码推导的调用链。日志时间顺序不能证明调用关系。
3. 追踪非法状态如何产生与传递、哪个边界缺校验。内存类假设结合故障指令、访问地址、寄存器和对象生命周期；相关缓冲问题参考[内存与缓冲](memory.md)。
4. 行号/调用关系解释不了现场时先核查版本差异、优化和符号匹配，不能硬套另一版本源码。未匹配区域降级为候选。
5. 单次 core 没看到锁冲突不能排除竞态。竞态、越界、UAF 等需要针对假设的复现、检测工具或所有权/同步证据，按现有环境和任务预算选择。

## 最小复现与修复验证

减图保留出问题子结构的实际端口、常量、属性、opset、dtype、shape 关系、上下游约束、编译入口和关键选项。每次缩减重跑，区分“该片段仍复现”与“只是结构相似”；不复现的片段不能充当已验证根因。改动产物另存并记录校验值。

优先用局部、可回退的修复或语义等价改写检验假设，遵守设计中允许改图/精度的范围。绕过 compiler pass 只证明当前路径避开故障，不能自动证明原 pass 的缺陷细节，也不能把不同 `graph_run_mode` 的现象直接归因于静态/动态图。

验证顺序为原触发条件、覆盖支持范围的功能与数值/业务精度、受影响并发和异常清理、稳定性，然后独立测量性能。等价改写需覆盖动态范围、索引/广播/边界语义；“编译成功”或“不再崩溃”不代表等价。报告修复与绕过的区别、版本适用范围、未覆盖场景，以及回退方法。所有尝试按本任务 OPT 记录保留最终接纳或撤回决定。
