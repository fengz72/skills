# 历史案例比较与基线校准

本包不附虚构历史性能案例。先搜索用户提供或当前可访问的项目验收报告、完整调优记录和原始测试结果。无需案例数据库或外部技能；没有历史也可用当前基线逐步校准，并降低预测可信度。

## 一份可用于数值推荐的案例

保留以下可比性信息和证据；无法核实的字段标未知：

- 模型/图/代码身份与规模，结构/主要算子、瓶颈、shape/长度分布、batch、dtype、计算精度与前后处理。
- 芯片、设备数、核/内存预算，CANN/驱动，GE Session 或 ATC→OM→ACL 路线，实例/并发与调度配置。
- p99 上限和计时边界、请求到达/突发方式、缓存/预热、测量窗口、请求数、重复轮次、p99 算法与跨轮判定。
- 成功吞吐、p99、错误/超时/丢弃、队列/积压和负载实际形成的证据；标明是搜索点还是冻结后的独立验收点。
- 首个可信基线、最终可行点、接纳/不接纳的优化、配置与完整记录，原始逐请求数据、结果和复现命令。
- 资源估计如果存在，保留其 F/D/P/B 定义、假设和来源，以便比较实现比例。

用于推荐的关键结果与可复查证据应随案例提供相对路径，或由本任务明确提供。只有旧机器绝对路径且当前无法读取的报告只能贡献优化线索，不能当成已验证 QPS 样本。可访问的报告也应检查其测试质量，不因标题写“验收”就采信。

## 比较而非按名字套用

优先匹配同芯片/资源、计算精度、SLO 计时边界、shape/请求分布与瓶颈，然后才看模型结构相似性。做简短比较表：可比字段、差异、差异的预期方向、校准证据、可用于定量推荐或仅作启发。

跨 CANN/驱动、路由、资源或计算模式外推，说明编译/调度/硬件差异及不确定性，不只按峰值 TFLOPS、核数或模型参数量线性缩放。失败、退化、超 p99、发生器无效或队列不稳的点帮助理解边界，不能混入已验收容量样本。

若多个案例有同口径资源容量估计，可比较 `独立验收的 p99 约束内吞吐 / 资源容量估计`。匹配程度、SLO 余量和调度影响这个比例；不能提炼为全模型通用常数，超过假设上界时先检查单位、工作量与测量身份。

## 校准循环

1. 建立初步资源/案例预测，列出依据与未知。没有足够证据时给测量计划或较低可信度定性建议，不能为继续任务伪造数值。
2. 正确性通过后，让测试在固定契约下取得负载—成功吞吐—p99 曲线，包含发生器发送滞后、错误/超时、资源和积压；对比当前理论假设中的计算、搬运与调度。
3. 更新区间与瓶颈优先级。目标推荐只用于规划，用户确认的最低吞吐、p99 或精度门槛不能因预测不准而移动。
4. 搜索完成后冻结实现与配置，以独立请求序列/种子及新轮次验收，最终只引用验收值。基线同规则；没有独立数据时至少新轮次并说明局限。
5. 记录预测偏差、修正原因、可行/不可行范围和预算内未探索项。高/中/低可信度是有说明的判断，不伪装为统计置信区间；有足够真实案例时才考虑留出案例预测校验。

初始无可行点时可将正确性/资源通过的中间方案用于下一轮可行性探索，明确它尚未性能通过；已有可行交付基线保留。首次可行写“从未可行到可行”，相对容量增幅不适用；预算结束仍未可行则性能未通过。

## 沉淀新案例

将最终报告、全部 OPT 记录与所需证据作为本项目案例，固定版本与相对路径；整体收益直接比较首个可信基线与最终包，不能累加每步百分比。预测偏差和无收益尝试同样有价值。

向共享 skill/案例包发布须先明确可共享范围，按需脱敏，不自动复制受限模型、业务数据、日志或绝对路径。没有可分享的原始证据时明确案例强度与使用边界，不把删去证据后的摘要继续当完整验证案例。
