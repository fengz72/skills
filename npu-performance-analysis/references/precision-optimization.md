# 低精度与混合精度优化

在保持原有数值和业务验收门槛的前提下，将降低计算/存储精度作为吞吐、时延或内存优化候选。SE 提出转换范围，开发隔离实现，测试对照独立参考验收，主控按实际收益决定接纳；不要求所有模型尝试同一种 dtype，也不预设低精度一定更快。

## 方案与模型边界

| 手段 | 可探索范围 | 必须核实 |
|---|---|---|
| FP32 → FP16 或 BF16 | 目标支持的权重、激活、MatMul/FFN 等计算 | 算子/shape/布局支持、动态范围、实际计算与累加类型、精度和内存收益 |
| 混合精度 | 主要计算使用低精度；敏感片段保留或回退 FP32 | 转换边界、Cast成本、融合是否受影响、最终整图精度 |
| 硬件降低有效计算精度 | 目标版本支持、设计允许的模式，例如 HF32 | tensor dtype可能仍是FP32，不能只看IO判断；模式和实际kernel须用当前SDK与执行证据确认 |

INT8/INT4 等量化涉及量化方案、校准/scale 和算子接入，不等于一次浮点 Cast；仅在设计允许时作为另一候选，不隐式混入 FP16/BF16 实验。

原图、权重和可信参考先固定身份。按已有用户授权与设计允许范围执行；只要求把此方法加入工作流，不表示某个仍明确限制 FP32 的模型已自动转换。已允许“满足精度门槛时可调整精度”的任务，无需为每个常规转换反复确认。支持范围、IO契约或业务门槛的改变另行收敛，不能为让候选通过而悄然扩大。

## 记录实际精度策略

每个候选明确四层，基线和候选分别记录：

1. 权重和外部数据的存储 dtype、转换工具/参数及产物校验值；保留原文件，候选另存。
2. 激活和各计算片段 dtype，哪些进入低精度、哪些保留或回退 FP32。
3. kernel 的计算、累加/归约精度，以及编译器允许的转换；tensor声明不等于实际执行精度，内部精度无法确认时标为未确认。
4. 输入输出逐张量类型及必须保持的接口；整数ID/索引、布尔语义按原契约处理，不因降低浮点计算精度就一起转成 FP16。输出可按接口保持FP32，转回FP32不恢复已丢失的数值精度。

PyTorch `.half()` 或 autocast 的结果，必须真实进入选定导出图和最终 GE/OM 路线。已有 ONNX/AIR 不会因修改一项 YAML dtype 名称就自动安全转换；图转换和编译精度策略分别核实。编译选项与 API 名称从实际安装SDK/同版官方资料确认，不提供未经核实的通用开关。

## 选择转换与回退片段

优先从有计算/内存证据且目标已有实现的片段提出候选。缺 profiling 时可以做支持性调查或结构假设，不能断言瓶颈和收益。先固定一个精度策略验证，不同时叠加多个不相关优化。

LayerNorm、Softmax、L2归一化、长归约、门控或最终相似度等是敏感性检查点；可先保留FP32，再按证据扩大低精度范围。它们不是永久排除名单：若目标低精度输入、FP32累加的实现或其他方案通过既定门槛，可作为候选比较。

- 检查 epsilon、倒数、归约、指数和大/小数范围。示例：`1e-12` 若实际转成FP16会变为0；是否发生取决于属性/常量和真实计算类型，不能只看输入dtype。
- 检查 mask、Inf/NaN 与全屏蔽行语义。FP32的最小有限值转换为FP16可能成为负无穷，需核对转换工具和算子的处理，不能无条件沿用。
- 检查每次Cast、布局变换和CPU/Host处理。转换过多可能破坏融合或让低精度更慢；发生在约定调用边界内的开销都计时。

## 验证、收益与记录

1. 从固定父快照创建独立候选，先建立或核验原精度参考。转换后的图检查IO、shape、dtype、常量/权重与算子支持；静态合法不代替设备可运行与精度。
2. 用同一原始参考比较完整输出和既定业务指标，包含TopK的ID、顺序和分数等实际要求。覆盖代表性动态shape、极端数值、零/近零、mask和排名边界，不用候选生成自己的expected，也不放宽阈值。
3. 失败时定位首个差异并将敏感片段回退FP32，记录新的候选策略。仍失败、非有限值、性能退化或无收益均保留记录；不以改参考或阈值换取通过。
4. 通过对应正确性后，在相同工作负载、资源和计时契约下测量。必要的输入/输出Cast、H2D/D2H和同步不省略。先做同参数A/B；若显存减少后再增加batch/实例，按相同资源预算另作容量搜索，并重新验证最终组合。
5. 搜索后冻结版本、实际精度策略与配置，用独立轮次验收吞吐/p99、压力正确性、稳定性和资源释放。若p99无上限，沿既有约定报告观察值，不虚构SLA。

实施前创建工作流规定的固定OPT记录，记录原精度基线、候选精度分布、生效证据、数值/业务误差、吞吐/p99、内存、转换成本和回退。只节省内存时报告内存收益，不能伪造吞吐提升；是否纳入最终包以独立验收为准。所有成功、失败、退化和未完成点进入最终汇总。

遵守本包[正确性约定](../../npu-model-workflow/references/correctness.md)、[测量约定](../../npu-model-workflow/references/measurement.md)和[设备可用性门禁](../../npu-model-workflow/references/orchestration.md#设备可用性门禁)。设备全忙时继续静态调查和离线准备，设备验证保持未运行。
