# 图与 kernel 归因

## 输入与身份

图分析是 profiling 的可选增强。缺 GE 图仍可做时间线与算子分析，报告未完成的图归因。可读取本次 GE Build 图、实际解析支持的源 ONNX、AIR 描述或 PyTorch FX；不用其他版本/构建的图冒充当前图。

原始 ONNX 说明源结构，不证明最终 GE 融合、layout、精度或调度状态。FX 只能在对应导出链路中解释源模型。纯 ONNX 不要求额外 PyTorch modeling 脚本。AIR 若没有可读图工具，利用本次编译导出和日志说明边界，不猜测内部节点。

先检查文件格式与当前可用解析方式：读取真实 schema/字段、节点边与属性，确认工具支持目标格式；不要只因扩展名为 pbtxt 就交给假设另一种 schema 的解析器。保存图身份、生成命令/阶段、shape/dtype 和关联构建信息。

## 建立可解释映射

1. 从本次图/模型 ID、节点名、编译映射信息或融合来源开始，将运行事件关联到编译节点。
2. 以类型、输入输出 shape/dtype、上下游和执行窗口交叉核对；名称截断、重命名、重复实例、融合后多对一都显式处理。
3. 为映射注明“已确认、近似、歧义、未映射”。仅靠算子类型平均耗时或模糊名称匹配只能近似归因，不能给出无歧义的逐节点成本。
4. 保留多对一/一对多关系，不给多个源节点重复分配同一 kernel 全部耗时后累加；无法拆分融合 kernel 时按融合组报告。
5. 将累计热点与时间线关键依赖对应。累计高成本不自动位于单请求关键路径，也不自动解释 p99。

## 筛选重复结构和融合机会

可先按算子序列、邻接和 shape/dtype 发现候选，再检查完整模式：数据/控制边、分支、广播、可选输入、常量、属性、外部消费者、多输出、索引边界、数值语义与动态范围。结构近似不等于可替换。

优先检查最终图已做的消除/融合和已安装实现，避免为已消失的源模式开发 pass。提供案例时核对其目标版本、前提与完整模式；没有案例库也能按上述检查形成实验，不要求安装来源技能。

对候选报告匹配位置/数量、对应实际执行成本、当前融合状态、理论可消除的搬运/提交和实施复杂度。收益预测保留依据和不确定性；重复次数多不能代替 profiling 成本。后续实际开发按[GE 优化方法](ge-optimization.md)验证注册、加载、命中和最终执行变化。
