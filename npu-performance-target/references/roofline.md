# Roofline 与资源容量估计

## 建模口径

固定业务单位（请求、样本或其他）、实际 shape/长度分布、batch、计算精度、芯片/核预算及执行图。区分源图与最终 GE 执行图，融合、layout 和类型转换会改变实际计算/流量。

对业务请求估计计算量 `F_req`（例如 FLOP/request）、HBM 实际读写量 `D_req`（byte/request）、匹配计算模式的可用速率 `P`（FLOP/s）和带宽 `B`（byte/s）。规定 MAC 是否计为 2 FLOP并保持一致，不能混用 GOPS、TFLOPS 与字节单位。

```text
算术强度 AI = F_req / D_req
匹配假设下的计算容量 = P / F_req
匹配假设下的访存容量 = B / D_req
资源容量估计 ≤ min(P / F_req, B / D_req, 其他已知资源容量)
```

按 batch 计算时可直接使用 `P/F_batch × 业务请求数_per_batch` 与 `B/D_batch × 业务请求数_per_batch`，明确权重读取摊销；勿把 batch 内样本数与请求数混为同一 QPS。

理论/规格容量在所列假设下才可称上界估计；微基准测得的速率是经验容量，不是所有算子的严格上界。零/未知工作量不参与除法，不将缺项视为无穷容量后声称完整结论。

## 获取 F、D、P、B

- **F：**按目标 shape 与算子语义计数，记录支持的计算类型、padding、稀疏或索引行为。对动态请求可给分 shape/长度成本和混合分布估计；平均成本用于资源筛查，不代表 p99 请求。
- **D：**根据实际数据路径估计 HBM 读写，区分片上缓存/重用、权重读取、激活、中间物化、布局转换和重复读。模型文件大小不等于每请求流量；HBM 字节、H2D/D2H 与片上流量分开。
- **P：**核实同芯片、核预算、dtype、Cube/Vector、稠密/稀疏与实际计算模式的资料。混合算子不能全部套用最高 Cube 峰值；必要时按不同执行资源分别分析其工作量和串行关系。
- **B：**说明是硬件规格还是同资源下的实测值。读/写、连续/随机访问的实际可达性不同；Gather/Embedding 的不规则访问、访存时延和并发不足可能使单一带宽模型偏乐观。
- 可用目标版本安装文档、官方硬件资料、现有可核实微基准或 profiling 计数校准。没有资料时报告范围/未知，不能编造全模型通用利用率系数。

## 不能漏掉的资源与依赖

检查 Host 准备/提交、H2D/D2H、同步、串行依赖、运行时调度、小算子、shape 切换与内存容量。可对有可靠容量数据的资源建立单独限制；没有数据则列未覆盖成本，而非隐含为零。

对低负载延迟分析实际依赖关键路径；并行 kernel 时间不能直接相加，关键路径倒数不能替代并发吞吐。若在可信假设下已知延迟下界超过 SLO，应说明可行性风险与可改变的假设，不能凭粗略 kernel 均值宣布不可能。

多实例共享物理资源。使用整卡计算或带宽后不能再乘实例数；增加实例可能提高利用率，也可能增加竞争、内存和尾延迟。容量估计只在固定设备/核预算内比较。

## 从估计到推荐

Roofline 不建模到达、排队、动态批处理等待、请求分布或尾部竞争，不能直接输出“满足 p99 的 QPS”。计算/访存容量用于辨别限制与优化空间，再结合[案例与实测校准](cases.md)形成推荐。

可给有明确来源的乐观/保守假设区间，逐项展示差异；不能为了输出区间任意套 30%/70% 等系数。历史实现比例只能来自口径可比、证据可读的案例；其范围并非统计置信区间。

先提出可承受的低负载测量，再按实验预算由粗到细增载；以真实 p99、错误、积压和资源验证可行点，冻结配置后独立验收。新的数据修正预测和假设，不自动改变硬性需求。
