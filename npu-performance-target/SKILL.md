# NPU 吞吐目标推荐

供 SE 制定预期和实验优先级。推荐值是预测；只有用户明确采纳为最低吞吐要求时才成为硬性验收门槛。工作流仍以固定精度、工作负载和资源下，p99 不超上限的可持续吞吐为目标。

## 方法

1. 读取模型设计：唯一执行路线、模型/shape/长度分布、dtype 与计算精度、p99 数值和计时范围、到达方式、核/内存预算、缓存假设，以及现有测试结果。缺业务约束时标明待决，不替用户编造。
2. 按[Roofline 与资源估计](references/roofline.md)计算可解释的资源容量与未覆盖成本；缺 F、HBM 流量或匹配硬件资料时列为未估，不以文件大小、其他 dtype 峰值或固定利用率替代。
3. 按[历史案例与校准](references/cases.md)读取当前可访问的证据，优先匹配资源、工作负载、SLO 与瓶颈。包内没有预置历史性能数字；没有可复查案例时依靠本次基线校准，不虚构“经验 QPS”。
4. 给出有依据的参考区间、可选代表目标、可信度、假设与下一次更新条件。证据不足以形成有用数值区间时，明确“暂无法数值推荐”，先给有限基线扫描计划，不输出伪精确预测。
5. 正确性通过后，由测试按[测量约定](../npu-model-workflow/references/measurement.md)扫描负载、batch、并发/实例并复验，更新预测。搜索结果与冻结配置后的独立验收结果分开，推荐随证据更新但不悄然移动已确认硬约束。

## 报告固定区分四类数值

| 类型 | 能说明什么 |
|---|---|
| 资源容量/上界估计 | 给定图、资源、精度与读写假设下的限制，不保证 p99 |
| SE 推荐吞吐区间 | 用于预算与搜索的预测，附依据、可信度和边界 |
| 实测可达吞吐 | 指定实现/配置在约定条件下，经测试验收的持续成功吞吐 |
| 最低吞吐要求（可选） | 用户明确确认的额外验收门槛 |

输出报告至少包含：对象/版本与 p99 边界、工作负载和资源假设、计算与流量口径/单位、容量估计及缺项、案例可比性与证据、当前基线、推荐区间或无法估计原因、优化方向、可信度和更新条件。每个数值标注预测、搜索或验收身份。

初始没有满足 p99 的点时，报告“尚无可行点”并建议优先改善可行性；首次可行写明状态转变，不从零/缺失基线计算约束内吞吐增长。预算结束仍无可行点不判性能通过。最终只声称预算内最佳已验证点，不声称全局最优。

项目结束记录预测偏差与原因、有效/无效优化和可复查证据。可共享范围明确后再纳入共享案例，避免自动复制模型、业务输入或受限日志。

方法的内化来源与适配记录见 [sources](../npu-model-workflow/references/sources.md)，随包保留适用许可；不以来源仓或外部同名技能为运行前提。
